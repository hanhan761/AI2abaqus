# 评测协议与过程性评价

## 将技术成果作为评测主体

研究对象是版本化的AI2abaqus技能及其约束、审查和核验机制。单一研究模型固定qwen3.7-plus；软件、任务、基线、时间/请求预算和参考方法均固定。不要通过更换模型混入方法差异。

可检验的问题：能否将给定条件落实为模型；能否发现软件完成但物理错误的结果；能否定位阻断环节并保留人工修正；能否提供足以复核的过程材料。

若要比较方法，预先定义相同任务与预算下的基线流程和skill流程；记录分配任务总数，不只展示成功案例。阶段消融可分别研究任务契约、审查支架、独立核验的作用。此处是后续评测设计，本版本没有运行这些对照或消融，不能写出提升百分比。

## 统计与证据单位

- 一项任务：固定task/case、skill版本、软件、模型、初始材料、预算与终止规则。
- 一次模型请求：有实际服务调用记录；历史响应回放的新增请求数为0。
- 一次软件提交：产生新的runs/rNNNN及终态；建模失败也记录。
- 清洁复跑：独立列出，不计作新的模型完成任务。
- 审查：记录实际角色、理由、源码前后哈希。开发者模拟教学不变成真实师生数据。
- 环境失败：许可不可用、机器不符、启动失败或超时单列，不能当成预期API故障，也不能据此评价模型正确率。

建议报告阶段通过数/固定任务总数、完整独立验收率、错误物理任务的拒收情况、审查介入次数/变更范围、证据完整性与反馈有效引用。真实学生的学习增益、评分一致性、反馈准确率必须另有课堂数据与教师标注。

## 五维量规

|ID|维度|权重|证据|
|---|---|---:|---|
|understanding|任务理解与力学假设|20|条件表、运行前预判、适用条件|
|ai_review|AI使用与代码审查|20|原始提问与回复、差异、采纳/拒绝理由|
|iteration|运行与迭代排错|25|真实日志、失败版本、原因与复跑|
|physics|结果与力学校核|25|实际INP、独立ODB/CSV、理论趋势与平衡|
|reflection|反思与可复现材料|10|贡献归属、局限、源文件和补交回应|

## 提交与反馈工具

将过程文件清单写成JSON，键为上表ID、值为会话目录内的相对路径；只提交已有材料。运行：

~~~text
python scripts/ai2abaqus.py submission --workspace workspaces/demo --process-files process_files.json
~~~

命令在submission/packets/sNNNN/evidence.json保存每版提交，并将submission/evidence.json更新为最新副本，同时返回版本号、路径及SHA-256。旧提交与其反馈均保留。F1是独立核验状态，F2是量规，F3是记录的预判；P_开头是提交的过程文本。过程文本的存在与哈希不证明其中叙述体现了真实理解，需教师复核。

向已授权的qwen服务提供该完整证据，要求只输出以下字段：evidence_sha256、dimensions、missing_evidence、next_actions。dimensions恰有五个不同ID，每项包括整数score、非空reason与引用已有ID的evidence_refs。将真实回复保存在文件后调用：

~~~text
python scripts/ai2abaqus.py feedback --workspace workspaces/demo --input feedback.json
~~~

工具拒绝过期证据、无效编号、越界分数、布尔伪整数和AI填写教师最终评分。收到的反馈与拒收原因分别保留。通过结构检查仅说明格式与引用有效，不代表教育评价准确。teacher_final_score保持空值；技术通过与建议总分分开。

补交应保留原submission与feedback，按版本建立新的过程文件及清单，重新收集证据，再生成新报告；旧反馈的evidence_sha256不得用于新提交。可在过程材料中说明父提交与新增内容。补交引起建议分变化只能说明材料变化，不能凭模拟材料宣称学习进步。

## 本版本证据边界

此前两个教学案例曾完成真实求解、独立核验、CAE重开和清洁复跑；都包含明确人工支架与修正。原始模型响应被抽取为本仓库的回放输入。每份回放记录标注来源收据哈希、原始旧代码与新代码，控制器重新绑定当前源码哈希；不假称新模型调用。

本次skill的最新代码测试、许可证状态与实际ODB组件测试见evidence/。任何未完成的完整重算都必须报告为未完成，不用此前通过记录替代当前端到端结果。

数据文件用途与来源见[data-provenance.md](data-provenance.md)。
