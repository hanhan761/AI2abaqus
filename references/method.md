# 方法与证据契约

## 方法的技术对象

AI2abaqus把一次AI辅助仿真组织成可追踪的状态转换：任务已定义 → 预判已记录 → 候选修改 → 已审查源码 → 软件完成 → 独立验收 → 提交反馈。每个转换都有对应文件与可失败的检查；模型解释不能直接将状态推进为“验收通过”。

当前自动化包括：目标机绑定、不可静默改变的任务契约、源码哈希与审查绑定、精确片段修改、不可覆盖的运行目录、真实终态检查、INP/ODB/CSV核查、CAE重开、清洁复跑、评价证据编号与拒收记录。

当前工具不提供任意Python脚本的安全沙箱，也不认证外部服务的模型身份。代码必须在已授权隔离环境审查后运行，原始调用收据另行保留。组合梁验收属于已声明的有限配置，不是通用有限元正确性证明。

## 任务契约

初次任务包含：单位制与方向、几何、材料与本构、界面、支承与定位、载荷分配、网格、输出位置/分量/平均方式、参考来源及容差。当前spec.json和case.json被哈希绑定；若需要合法更改任务，创建新的任务版本。

预判应在运行前说明可观察结果与理由。例如：绑定梁中性轴为弹性模量加权位置；无摩擦滑移、保持接触的理想化下，各层中性轴靠近自身形心。三维有限元与理想梁理论的差异应分析，不用理论预判替代ODB取数。

## 六项上下文与局部修改

1. 背景：实验目标、学习者已有知识与软件环境。
2. 已知：本次问题相关的力学和对象信息。
3. 范围：准确旧代码、变量含义、缩进、允许改动的位置。
4. 证据：实际软件日志；若尚未运行，要如实说明。
5. 保护：不得改变的材料、支承、载荷、界面或提取定义。
6. 交付：新代码、修改理由、需要复核的问题和预期物理趋势。

patch命令只保证精确替换、源码哈希和Python语法；这些检查不证明API存在或物理完整。review命令要求实际审查者说明采纳或拒绝理由，run命令据源码哈希防止沿用旧审查。模型候选与人工修正分开保存。

## 运行和独立核验

每个run保存当时的build.py/case.json、实际运行日志、终态与工件哈希。完整运行要求实际终态、CAE/INP/ODB/CSV存在且非空。独立提取器通过Abaqus Python读ODB，与候选脚本导出的CSV核对。输入审查检查实际关键字而非源码中是否出现特定单词。

verify默认完成原始结果核查、保存CAE的重开导出审查，以及从执行时源码的清洁复跑。它只接受先前记录中完整运行的工件，工件被改写会拒收。重复验证生成新verification目录，保留旧结论。中断后先看原目录与进程终态，再决定有依据的恢复动作。

工作区的hostname绑定避免复制任务后误在另一台机器执行；它不是账户认证或访问控制。现场机器的授权、许可与服务配置仍由使用者建立。命令不记录环境变量、口令或密钥。

## 输出与归属

会话根目录的report.json/report.md给出最近一次完整核验。patches、reviews、runs、verification和submission保留过程。kind区分developer-demo、mock和student；仅有真实学生材料时使用student。复现时同时记录skill版本、脚本哈希、软件版本、任务契约、模型服务标识与人工介入。无实际来源的过程说明不能转写成学生表现。
